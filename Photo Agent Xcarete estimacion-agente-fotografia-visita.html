Estimación de queries por interacción:
  • Path A (caso existe): 2–3 queries (identidad + perfil + historial de casos)

Nota: El consumo de queries de Data Cloud depende de la implementación específica. Si las consultas de casos se hacen directamente a Salesforce CRM (SOQL) en lugar de a Data Cloud, el consumo de queries DC podría ser menor (1–2 por conversación, solo para resolución de identidad y perfil unificado). Confirmar con el equipo de arquitectura qué datos se consultan vía Data Cloud vs. SOQL directo.

4. Lógica de Consolidación

Acciones consolidadas: La creación del caso, asignación a cola, tipificación y registro de trazabilidad se ejecutan como un solo Flow invocado como una acción, no como 4–5 acciones separadas. La consulta de casos previos y la validación de duplicidad se resuelven en una sola query.
Queries consolidadas: Si se utiliza Data Cloud, la resolución de identidad y la obtención del perfil unificado pueden consolidarse en 1–2 queries dependiendo del modelo de datos. Las queries de historial podrían ejecutarse directamente contra CRM si los casos no están ingestados en Data Cloud.
HU 59 (modo informativo sin envío automático de archivos) es un guardrail de comportamiento del agente, no una acción facturable ni una query.

5. Supuestos para Estimación Blended

  • ~40% de conversaciones encuentran un caso previo (Path A)
  • ~50% de conversaciones requieren crear caso nuevo (Path B)
  • ~10% incluyen escalación a humano
  • Data Cloud se utiliza para resolución de identidad y perfil unificado
  • Consultas de casos se realizan vía SOQL directo a Salesforce CRM
